The product

One workload. Multiple execution paths. One acceptance gate.

EXUP optimizes the execution of a workload, not allegiance to a particular model, provider or hardware stack. The economic baseline and acceptance boundary are locked first.

01

Baseline workload

Lock the current workload, accepted result, volume, cost, latency and reliability.

02

Acceptance gate

Define what must remain true: quality, task success, latency, reliability, security or resource limits.

03

Candidate execution paths

Compare permitted model, runtime, provider, routing, batching, cache, timing or hardware alternatives.

04

Verified result

Run the same workload. Any candidate that misses the acceptance gate is rejected even when it is cheaper.

05

Cost per verified result

Select only a lower-cost path that still satisfies the locked contract and preserve the evidence.

Baseline workload → Acceptance gate → Candidate execution paths → Verified result → Cost per verified result

External routers, providers, GPU markets and local hardware can be execution venues. They are inputs to EXUP, not the control plane. Search policy, candidate generation, scoring, prompts, heuristics and next-action logic remain private.

Problem

AI improvement is fragmented across the stack.

Data, training, evals, agents and inference are usually optimized as separate disciplines. That forces teams to guess where the next gain is. EXUP treats the permitted AI system as the improvement surface and tests changes against the business objective.

Savings logic

Turn measured improvement into your economics.

The benchmark freezes the economic baseline before optimization. Savings may come from lower compute/provider spend, less host-time, lower hardware cost, fewer retries, less human intervention or more capacity from the same budget — but only for a candidate that passes the acceptance gate.

Verified savings = baseline cost − accepted candidate cost.

For a customer workload, attribution rules are fixed before the benchmark. Technical improvement is not automatically economic value; it becomes value only when it changes a real cost or capacity metric.

PUBLIC-01 is the example: +23.2% throughput translates to 18.9% less host-time for the same million-image workload. The customer then applies its actual host/provider economics.
