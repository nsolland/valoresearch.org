Find the smallest ST-based reference architecture for retrofit intelligence.

A bounded technical path from local inference, secure identity and physical interfaces to governed real-world action — without tying the architecture to one silicon generation.

The engineering question

The installed world is the target: sensors, cameras, switches, cabinets, machines and actuators that should gain local intelligence without requiring full replacement.

The immediate question is deliberately narrow: what is the smallest practical ST-based reference architecture that can support local inference, secure identity, physical interfaces and enough headroom for different model classes — and where is the practical boundary between STM32-class devices and more capable ST edge AI options?

What we believe

Carrier-neutral by design

The durable object, identity and authority contract should survive replacement of the compute or model carrier. Silicon should implement the architecture, not define it.

Local first

Sensing and inference should stay local where that reduces latency, bandwidth, cloud dependence and unnecessary data movement.

Govern only consequence

Not every inference needs heavyweight control. The authority check becomes mandatory when a node can create a real-world effect.

Proposed next step: one bounded ST reference matrix

Define three target nodes — Sense, Perception and Action — and map the smallest suitable ST class for each against memory, compute, power, interfaces, security primitives and deployment tooling.

Choose one minimal prototype path, deploy a representative local model, bind identity and the physical effect boundary, and test whether the same higher-level object and authority contract survives a change of compute or model carrier.

The output is not a broad product programme. It is a reference architecture, measured constraints, a working demonstrator and a clear decision on where STM32-class hardware is sufficient and where a more capable ST option becomes necessary.

Open questions

  1. What is the smallest STM32-class configuration that can support the Sense and basic Perception roles without compromising the architecture?
  2. Where does ST see the practical boundary between STM32-class devices and more capable edge AI hardware for local vision, audio or richer models?
  3. Which secure identity and device-root primitives should be part of the reference design from the start?
  4. Which physical interfaces and development boards give the fastest path to a real sensor-to-action demonstrator?
  5. Which model classes should be used to make the carrier-substitution test technically meaningful rather than synthetic?
